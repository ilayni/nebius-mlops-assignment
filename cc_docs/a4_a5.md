# A4 + A5 Implementation Summary

## What was built

### `agent/prompts.py`
Four concise string constants: `GENERATE_SQL_SYSTEM/USER` and `REVISE_SQL_SYSTEM/USER`.
No verify prompt — verification is programmatic (cheaper and more reliable than asking the LLM).

### `agent/graph.py`
Full LangGraph agent with inline Langfuse tracing.

**Graph topology:**
```
generate_sql → execute_sql → verify ─── success ──→ END
                                  └─── error, iter < 3 ──→ revise → execute_sql → ...
                                  └─── error, iter >= 3 ─→ END
```

**Key design decisions:**

| Decision | Choice | Why |
|---|---|---|
| LLM client | `openai.OpenAI` directly | Works with both Token Factory (local) and vLLM (H100) via env vars only |
| verify | Programmatic (sqlite exception check) | More reliable, cheaper, no hallucination risk |
| Zero-row result | NOT an error | COUNT/aggregates return `{count: 0}`, WHERE filters can legitimately match nothing |
| SQL extraction | Strip `<think>` blocks → try fences → try first SQL keyword | Qwen3 emits reasoning blocks and often wraps in markdown |
| Iteration cap | Explicit `iteration >= MAX_ITERATIONS` in router | Prevents `GraphRecursionError`; MAX_ITERATIONS = 3 |
| Langfuse availability | Silently disabled if `LANGFUSE_PUBLIC_KEY` unset | Agent runs without Langfuse configured |
| `langfuse.flush()` | Called on both success and exception paths | v2 sends on background thread — without flush, traces are lost on short scripts |

**Langfuse trace structure per question:**
```
trace: text-to-sql
  metadata: question_id, db_name, iteration_count, final_status  ← set via trace.update() at end
  span: generate_sql
    generation: llm  (input tokens, output tokens from response.usage)
  span: execute_sql
  span: verify
  [span: revise
    generation: llm]  ← repeated up to MAX_ITERATIONS times
```

**Public entry point** (what A6 calls):
```python
from agent.graph import run

result = run(
    question="How many employees earn more than 80000?",
    db_path="employees.db",
    question_id="q1",
    db_name="employees",
)
# returns: {predicted_sql, result, iterations, final_status, error, latency_s}
```

## Testing checklist

### Prerequisite: configure .env
```
OPENAI_BASE_URL=<Nebius Token Factory endpoint>
OPENAI_API_KEY=<your ToFa key>
VLLM_MODEL=<model name on ToFa, e.g. Qwen/Qwen3-30B-A3B-Instruct>
LANGFUSE_PUBLIC_KEY=<from localhost:3001 after signing up>
LANGFUSE_SECRET_KEY=<from localhost:3001>
LANGFUSE_HOST=http://localhost:3001
```

### Test 1 — happy path (no revise)
```bash
python - <<'EOF'
import sqlite3, tempfile
db = tempfile.mktemp(suffix=".db")
conn = sqlite3.connect(db); conn.execute(
    "CREATE TABLE employees (id INTEGER PRIMARY KEY, name TEXT, salary INTEGER)"
); conn.execute("INSERT INTO employees VALUES (1,'Alice',90000),(2,'Bob',75000)")
conn.commit(); conn.close()

from agent.graph import run
result = run("List all employee names", db, "q_happy", "employees")
print(result)
EOF
```
Expected: `final_status=success`, `iterations=0`, SQL executes cleanly.

### Test 2 — revise path (force at least one revision)
Use a question that references a column name that doesn't exist in the schema.
The model will likely hallucinate a plausible column name; sqlite will raise, triggering revise.
```bash
python - <<'EOF'
import sqlite3, tempfile
db = tempfile.mktemp(suffix=".db")
conn = sqlite3.connect(db); conn.execute(
    "CREATE TABLE orders (order_id INTEGER PRIMARY KEY, amount REAL, status TEXT)"
); conn.execute("INSERT INTO orders VALUES (1,99.9,'shipped'),(2,45.0,'pending')")
conn.commit(); conn.close()

from agent.graph import run
# "customer_name" does not exist — model may hallucinate it
result = run("What is the total amount for each customer_name?", db, "q_revise", "orders")
print(result)
print("Iterations (want >= 1):", result["iterations"])
EOF
```

### Test 3 — Langfuse trace visible
After running either test above:
1. Open http://localhost:3001
2. Go to Traces
3. Confirm trace named `text-to-sql` appears
4. Click into it — verify `generate_sql`, `execute_sql`, `verify` spans are nested
5. Check the `llm` generation child has non-zero token counts
6. Check trace metadata shows `iteration_count` and `final_status`

### Test 4 — max iterations cap
```bash
python - <<'EOF'
import sqlite3, tempfile
db = tempfile.mktemp(suffix=".db")
conn = sqlite3.connect(db); conn.execute("CREATE TABLE t (x INTEGER)")
conn.commit(); conn.close()

from agent.graph import run, MAX_ITERATIONS
result = run("JOIN nonexistent_table ON fake_column = other_fake", db, "q_cap", "t")
print("final_status:", result["final_status"])
print("iterations capped at:", result["iterations"], "(max=", MAX_ITERATIONS, ")")
EOF
```
Expected: `iterations == MAX_ITERATIONS`, `final_status=error`, no `GraphRecursionError`.

## Test results (Qwen/Qwen3-30B-A3B-Instruct-2507 via Token Factory)

| Test | Result | Iterations | Latency |
|---|---|---|---|
| 1 — happy path | success | 0 | ~0.6s |
| 2 — revise (JOIN missing table) | error after 3 revisions | 3 | ~1.7s |
| 4 — iteration cap | stopped cleanly, no crash | ≤3 | — |

**Key finding:** the model is smart enough to avoid bad columns on its own — when asked about
`department_name` on a table without it, it substituted `status` and succeeded without revising.
Revise only fires on genuinely impossible SQL (missing table, syntax error).

This matters for A6 eval metrics: "pass on iter 1 vs iter 2+" measures whether the LLM needed
error feedback to correct its SQL — not whether it hallucinated column names.
